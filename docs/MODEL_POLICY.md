# 모델과 토큰 사용 규칙

모델 배정의 정본은 `kit/model-policy.json`이다. 이름은 이 환경의 초기 배정값이며 가격표나 모든 계정에서의 사용 가능성을 보장하지 않는다. 계정에서 지원하지 않는 모델이면 오류를 알리고 지원하는 동급 모델을 설정한다. 상위 모델로 조용히 대체하지 않는다.

- 실행기는 Codex 코디네이터를 기본 `gpt-6.1-terra`, Claude 코디네이터를 `sonnet`으로 시작한다. 메뉴 또는 `--model`에서 이번 코디네이터 모델을 변경할 수 있으며 워커 배정은 JSON을 따른다. 이미 열린 대화의 모델은 변경하지 않는다.
- 코디네이터는 worker-start마다 역할의 tier를 제공자 모델 ID로 변환해 `--model <ID>`로 전달한다. 프롬프트에 모델 이름만 쓰는 것은 모델 전환이 아니다. 요청 모델과 영수증에서 확인한 실제 모델을 구분해 기록한다. 실제 모델을 확인할 수 없으면 미확인으로 남긴다.
- 경량 작업: 요구사항 추출, 범위가 명확한 조사, 표·수치 대조. 일반 작업: 목차, 집필, 네이밍, 심사, 조율.
- deep(Astra/Opus)는 일반 모델로 한 번 수정해도 해결하지 못한 논리 충돌, 복잡한 방법론 판단, 사용자 명시 요청에 한정한다. 핵심 문제와 근거만 전달하고 이유를 기록한다. Run당 최대 1개 작업이며 초과가 필요하면 범위를 줄이거나 사용자에게 이유를 설명한다. 단순 최종 확인만으로 승격하지 않는다.
- single 모드는 실행 중 역할별 모델 전환을 보장하지 않는다. 역할별 절약은 orchestrated 모드를 사용한다.
- 조사 4개 파일은 유지하되 관련 없는 범위에는 생략 이유를 남긴다. 단순 조사는 1명의 워커가 묶어서 수행하며 최대 동시 2명이다. 단순 네이밍은 1명으로 시작한다.
- 워커에게 전체 대화·저장소·완성 보고서를 반복 전달하지 않는다. 필요한 파일 경로, 관련 발췌, 완료 조건만 준다. 이미 확보한 출처를 재사용하고 변경된 부분만 재검사한다.
- 네이밍 후보 기본 12개 → 상위 3개, 수정 기본 1회. 보고서 심사 상한은 WORKFLOW.md를 유지한다. 워커 완료 메시지는 결과 경로·핵심 발견·미해결만 10줄 이내로 작성한다.
- 상태 확인은 파일 조회와 Orca의 읽기 전용 조회로 수행한다. 상태를 보기 위한 새 AI 대화·워커를 만들지 않는다.
- 토큰은 런타임이 제공한 실측만 기록한다. 미제공은 null/미수집이다. 추정치로 사용량이나 절감률을 단정하지 않는다.
